## 一、产品本质（一句话）

**投后数据 AI 工作台**：把分散的文件（财报/GP季报/资本账户表/分配通知/股权表）变成可信、可计算、可追溯的结构化数据，并基于此提供看数、问数、导出能力。

## 设计过程记录（最新共识）

### [已确认] 2026-08-02 | 文件解析详情页与配置中心边界重构

- **目标**：将文件解析从“单文件财报 OCR 确认页”改为“项目维度的多文件结构化数据编辑与入库工作台”。
- **样例范围**：Demo 样例必须来自 `/Users/ctt/project/finstep/众源资本/财跃系统测试材料/`，覆盖 GP 季报/投资管理报告、资本账户表、托管人报告、权益明细/财务报表、IRR/估值成本 Excel、分配通知、分配明细、直投企业财报等实际类型。
- **项目维度**：同一项目/子基金的多份文件属于同一次数据处理任务。左侧切换和查看多份原文，右侧不按文件分隔，而按基金基础信息、投资、退出、期末持仓、资本账户、分配等业务数据组织。
- **文本数据**：不单独设计“AI 摘要”。业务进展、退出规划、后续融资、重大事项等作为结构化长文本字段存储和编辑。
- **直接修改**：取消逐字段“接受/驳回”。用户直接修改字段、单元格和长文本；明细表支持新增行、删除误识别行和修改单元格。
- **补充文件**：详情页允许继续上传补充文件，新结果合并到当前项目数据，并提示新增、覆盖和冲突数量。
- **保存方式**：编辑过程自动保存为草稿；用户完成后点击“确认写入项目”，再形成正式数据。
- **原文值与计算值**：文档披露的合计/指标必须提取和保留；系统同时从明细数据工程化重算。原文披露值、系统计算值和差异同屏展示，用户可选择最终采用值或手工填写；三者及其溯源都不丢失。
- **计算原则**：合计、余额、DPI、TVPI、MOIC、IRR 等需计算的数据由公式从明细值生成，不直接把文档合计数当作系统计算结果。修改底层明细后自动重算，保留公式、输入、版本和计算时间。
- **冲突处理**：多份文件的同一字段不一致时，展开显示各来源值，用户直接修改最终值，不强制从候选值中二选一。
- **原文归档**：确认写入后，原始文件同步归类到对应项目档案，并保留字段到页码/Sheet/单元格的溯源关系。
- **配置中心权限**：机构管理员统一维护默认业务配置，投资经理不选择“解析方案”。文件类型、版式和 PDF/Excel/OCR 解析方式属于平台能力，不属于机构配置。
- **机构配置内容**：标准财务科目及别名、基金/持仓/分配等标准字段及别名、合计与指标公式、试算平衡/勾稽/差异容差、期间标准化与派生规则、字段写入与档案归类规则。
- **业务用户介入边界**：系统无法确定项目归属、报告期间、当期/累计、实际/预测、合并/母公司、字段映射或公式必要输入时，才由投资经理处理业务事实歧义；不允许其修改机构级公式和映射配置。
- **配置版本**：管理员发布的新配置只影响新上传文件。历史任务保留原配置版本；管理员或投资经理可主动选择“按新配置重新计算”。
- **配置发布**：机构同时只有一个生效版本，并保留一个编辑草稿和历史版本。管理员在草稿中修改后直接发布；不要求上传样例文件试跑，不设发布前测试或校验门槛。
- **版本恢复**：管理员可选择历史版本并“恢复发布”，系统以该历史内容生成一个新的生效版本，不改写旧版本及原版本链。
- **后续决策原则**：未涉及业务口径的交互与工程细节，按“最少页面、最少用户选择、覆盖真实测试材料、保留数据溯源”原则由产品设计直接收敛。
- **旧规格覆盖说明**：本条目覆盖本文后续“接受/修改/驳回”、“逐字段接受/驳回”和“单文件确认页”的旧描述；待方案整体定稿后统一重写相关章节。
- **范围边界**：当前仅记录已确认产品共识，未开始详情页和配置中心的代码实现。

## 三、核心交互流程（5 步 · 主路径）

### Step 1 · 上传文件
- 入口 3 处：文件解析页 / 项目详情"上传材料" / 首页拖拽 → **自动归一到文件解析页**
- 行为：点击/拖拽 → **立即弹"AI 建议确认条"**（3 文件示例，每文件一行：文件名 | AI建议类型（标签）| AI建议归属项目（可改）| AI建议期间（可改）| "AI 建议"小标识）→ 底部按钮"取消 / 开始解析"
- 上传后**自动开始解析**（不再需要用户再点开始）→ 进度条+阶段轮播（识别版式→提取表格→映射字段→执行校验，3 秒一轮播）→ 8 秒后**自动跳转到待确认文件对应的确认页**
- 关键 UI：明显的输入框/上传区；右侧"AI 建议"标签弱化；底部品牌蓝"开始解析"按钮

### Step 2 · 确认页（左原文右候选）
- 顶部品牌蓝 header：←返回 | 文件名 · 客户 | **试算结果红字警示条**（"试算平衡：不平 12 项，通过 6 项，查看明细"） | 删除非当期列 | 导出 | 暂存 | **提交确认（蓝色大按钮）**
- 第二行 Tab：资产负债表 | 利润表 | 现金流量表（差异行粉橙高亮的原文在左）
- 第三行提示：左侧原表，右侧"财报数据"+"试算平衡"+"修改记录"Tab
- 主区左右两栏：
  - 左：原文表格（行号·科目·期间列），**差异行粉橙底色高亮**（试算不平时）
  - 右：候选字段表（行号·科目·源值·映射值·来源标签·接受✓·驳回✕·定位列）
- 关键 UI：差异行颜色对比明确；定位列可点击→左原文滚动+高亮；接受/驳回 inline 操作

### Step 3 · 确认后联动
- 确认写入 → toast「已写入 星河智造 · 2026H1 · 47 字段」→ 自动跳到下一份待确认（批次）
- 项目详情期间数据表新增该期列，与上期并排；超阈值科目带"↑52%"红色 badge
- 更新记录 +1：谁、何时、从哪份文件、改了哪些字段

### Step 4 · 盘面视图（消费侧）
- 项目库投后 Tab 顶部切换"列表 / 盘面"
- 盘面：按投资阶段表（项目数·投资金额·持股价值）+ 双环图（内圈投资金额/外圈持股价值）
- 表头一行："数据截至 2026-06-30 · 全部来自已确认数据 · 模板可在配置中心调整"

### Step 5 · AI 问数
- 首页 Chat 输入 → 答案卡：大数字 + 可展开计算过程（公式+输入字段+数据版本）+"来自已确认数据"标签 + 溯源链接 + "钉到盘面"按钮

## 五、UI 规范

### 5.1 颜色（4 色克制）

| 用途 | 颜色 | 使用 |
|---|---|---|
| **品牌蓝** | `#1a66ff` | 主按钮、阶段条当前、激活 Tab、关键提示 |
| **警示红** | `#dc2626` | 试算不平、异常状态、变动 ↓、错误 |
| **成功绿** | `#16a34a` | 试算通过、已确认、变动 ↑（正向） |
| **中性灰** | `#6b7280` | 标签、辅助文字、未激活 Tab |
| 紫（AI） | `#9333ea` | 仅用于 AI 兜底、股权事件（克制用） |

> 标签收敛：阶段（投前灰/投中蓝/投后绿）、类型（直投蓝/子基金灰）、来源（提取绿/派生蓝/人工橙）、状态（待确认黄/已确认绿/异常红）、AI 兜底紫——**同一屏最多 4 色**。

### 5.2 分隔线

- 页面分区之间：`border-top: 1px solid var(--xb-border)`（浅灰）
- 面板标题与内容之间：`border-bottom: 1px solid var(--xb-border)` 在面板头底部
- 表格行之间：`border-bottom: 1px solid var(--xb-border)` + hover 浅蓝底
- 不用粗黑线，不用色块分割

### 5.3 输入框（明确的可输入性）

- 圆角 8px，`border: 1px solid var(--xb-border)` 默认
- 聚焦：`border-color: #1a66ff`，加 1px 外阴影（`box-shadow: 0 0 0 3px rgba(26,102,255,.1)`）
- 占位符：`color: var(--xb-muted)`，明确写"输入..."或"拖入..."
- 输入框右侧带操作按钮（提问/发送）

### 5.4 标签（po-tag）

- 圆角 10px，`padding: 2px 8px`，`font-size: 11px`
- 中性背景 + 中性前景（不刺眼）
- 仅在必要时使用，不用作装饰

### 5.5 字体层级

- H2（页面标题）：17px / 700
- 区块标题（H3 / 面板标题）：13px / 600
- 正文：13px / 400
- 辅助说明：12px / 400 / 灰
- 数字：14-16px / 600 / 品牌色（突出）

## 七、验收要点

1. **首页输入框一眼可识别**：圆角+边框+聚焦高亮+按钮
2. **分隔线清晰**：面板之间、行之间有 1px 浅色分隔
3. **标签颜色克制**：同屏 ≤4 色
4. **上传自动解析**：点上传区→弹 AI 建议确认条→确认后自动开始解析并跳转到该文件确认页
5. **确认页"干活感"**：顶部品牌蓝 header、试算红字、大蓝色提交按钮、Tab 切换报表、左原文表格（差异行粉橙高亮）+ 右候选字段表
6. **盘面视图双环图清晰**：图例在右，颜色与表格对应
7. **阶段条显眼**：当前阶段品牌蓝填充，非当前阶段灰
8. **subagent 验收**：每个交互点都能点，状态流转符合文档
